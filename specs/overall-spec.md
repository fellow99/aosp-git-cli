## 1. 系统用途与目标用户

### 1.1 一句话

本系统以 **AAR 形式发布 Android 版 `git` 命令行可执行**：一个在终端（PTY）里经
`forkpty` + `execve` 启动的**独立进程真 `git`**（arm64-v8a），https 传输开箱可用，
git 模板与 CA 根证书随包携带；本系统交付的是它的**可复现构建、ELF 门禁与发布流水线**，
**不含任何嵌入 API**。

### 1.2 目标用户

| 用户 | 他们要什么 | 本系统给什么 |
|---|---|---|
| **终端类 App 开发者**（主用户/消费方） | 在自己的 App 里提供真 `git` 命令，不碰交叉编译、ELF 属性、SELinux 细节 | 一个 AAR 依赖（exec 型二进制 + 随包数据）+ 接入契约（规划 §7.1 env 注入表） |
| **本仓的实现者** | 知道每一步做什么、按什么顺序、怎么算完成 | 规划 §10 任务分解 + 本规格的 FR/验收判据 + 测试索引 |
| **CI/发布责任人** | 一条流水线产出可校验、可发布的制品，且不误发 | 门禁 + 发布卫生（两段式、显式开关、凭据零入库） |
| **合规/上架责任人** | 证明「许可齐备、GPLv2 义务履行、无运行期下载可执行物」 | 第三方许可清单 + 对应源码归档纪律（C7/D7） |

### 1.3 非目标（明确不做）

1. **不做嵌入 API**：无任何 Kotlin/Java/C 接口面——本仓只有原生二进制与随包数据的构建、门禁、发布。
2. **不做 ssh 远程传输**：`git@…` / `ssh://` 需另带 ssh 二进制，**二期再议**（规划 §1.3/§9.4）。
3. **不做 perl/tcl/python 依赖的子命令**：send-email / svn / gitk / git-gui / cvsserver / mergetool /
   `git p4` 明确不编（MUST NOT 随包承诺）；仓库钩子（hooks）运行期**不可执行**，git 视为无钩子。
4. **不做服务端角色**：`git daemon`、托管型 receive-pack 不在范围。
5. **不运行期下载任何可执行物**：全部随包预置（宪法 C2 边界）。
6. **不做多 ABI**：只发布 AArch64（arm64-v8a）。
7. **v1（M0）不交付 git 本体**：本体交叉编译属 M1（规划 §10）；本阶段只交付骨架、门禁与事实源纪律。

## 3. 系统边界

### 3.1 在范围内

| 域 | 内容 |
|---|---|
| 工程骨架 | 根工程与唯一模块的坐标、打包口径（exec 型）、版本纪律（独立 semver） |
| 构建输入 | 四源（git/zlib/curl/openssl）+ CA bundle 的钉选、下载、SHA-256 校验，**不改源** |
| 交叉编译 | NDK 交叉编译为 exec 型 PIE；静态依赖链入；16KB 页对齐；strip |
| 供给与门禁 | 事实源锁文件；exec 型 ELF 七门禁；幂等投放；jniLibs 白名单（禁入外部引擎库） |
| 随包数据 | git 模板、CA bundle、helper 农场清单的随包、物化与逐文件 sha256 出处记录 |
| 发布 | 两段式（归档先行、公共坐标随后）；许可清单与 **GPLv2 对应源码义务** |
| 运行期契约 | env 注入表与已知限制的**定义**（实现归消费方，规划 §7.1/§7.2） |

### 3.2 不在范围内

窗口/页面/UI · PTY 终端本身（消费方提供）· ssh 远程（二期）· perl/tcl/python 子命令 ·
服务端角色 · 运行期下载 · 非 arm64 ABI · 「崩溃自动重启」类语义（exec 子进程由终端层管理生命周期）。

## 4. 功能需求（RFC 2119；编号沿用 FR-000-xxx）

> 每条给出**可证伪的验收判据**；无判据的需求不得进入实现。现状列区分 ✅/⬜。

### 4.1 工程骨架（FR-000-001 ~ 005）

| 编号 | 级别 | 需求 | 可证伪的验收判据 | 现状 |
|---|---|---|---|---|
| FR-000-001 | MUST | 根工程有唯一名称，且只包含唯一的制品模块 | 干净工程对模块任务求值成功；工程名与坐标 artifactId 一致 | ✅ |
| FR-000-002 | MUST | 制品模块是 Android 库容器：无任何自有程序源码；命名空间、最低系统版本、编译目标版本、ABI 集合符合规划 §2 | 产出的 AAR 内无代码字节码（类存档为空）、清单由命名空间合成、ABI 目录仅 arm64-v8a | ✅（✅ 实测 debug AAR 类存档为空） |
| FR-000-003 | MUST | 发布坐标 = 固定 groupId + 模块名 + **CLI_VERSION**；CLI_VERSION 等于 git 上游版本（独立 semver），未设置时构建必须报错而非静默默认 | 删除该属性后配置期即失败；坐标三段与属性逐字一致 | ✅ |
| FR-000-004 | MUST | **exec 型打包**：原生库必须以「解包落盘」方式打包（与进程内 dlopen 库的口径相反） | 打包配置显式开启 legacy 落盘；安装后物理件存在于应用 native 库目录 ⬜（M1-T7 探针） | ✅ 配置 / ⬜ 落盘 |
| FR-000-005 | MUST | **无二进制时构建配置与任务求值必须成功**（二进制缺失不阻碍配置期） | 干净工程的任务列举构建成功 | ✅（TC-01） |

### 4.2 事实源纪律（FR-000-010 ~ 013 族）

| 编号 | 级别 | 需求 | 可证伪的验收判据 | 现状 |
|---|---|---|---|---|
| FR-000-010 | MUST | 存在**唯一事实源锁文件**：版本、ABI、大小、SHA-256、门禁结论、出处、发布状态 | 锁文件可 diff 审计；每个制品条目字段齐备 | ✅ |
| FR-000-011 | MUST | **draft 不伪造哈希**：未构建的条目大小为 0、哈希为空，并显式标记 draft | draft 条目哈希字段为空串且状态为 draft；首个真实构建后回写 | ✅ |
| FR-000-012 | MUST | 制品来源登记构建出处：上游源码、静态依赖、随包数据、工具链、构建参数 | builtFrom 各子项有值（draft 期允许 TBD/文本描述；M1 升级为依赖版本表 ⬜） | ✅（部分 ⬜） |
| FR-000-013 | MUST | 版本升级 = 锁文件增项 + 重新构建，**不允许**绕过锁文件发布 | 发布产物可回溯到锁文件条目；二者不一致即门禁失败 | ✅（纪律）/ ⬜（首次升级演练） |

### 4.3 供给与门禁（FR-000-030 ~ 036 族）

| 编号 | 级别 | 需求 | 可证伪的验收判据 | 现状 |
|---|---|---|---|---|
| FR-000-030 | MUST | 投放/校验工具的退出码契约：**0** 全过 · **2** 门禁不合格或未投放 · **1** 用法/IO 错误 | 三类场景实测退出码逐一对上（未投放=2；缺参数=1） | ✅（0 路径待 M1 ⬜） |
| FR-000-031 | MUST | exec 型 ELF 门禁七项：动态可执行形态、解释器恰为系统链接器、AArch64、依赖白名单、哈希一致、大小一致、16KB 页对齐 | 七项逐项有 ✓/✘ 输出；任一不满足即拒绝投放（exit 2） | ✅（对真实产物的⑦项实证 ⬜ M1） |
| FR-000-032 | MUST | **draft 只记录不比对**：哈希/大小无锁值时记录实测值并告警，不判定失败 | draft 期校验输出含「仅记录」语义且退出码不为 1 | ✅ |
| FR-000-033 | MUST | **仅投放本工具二进制**：目标目录内出现任何其它 `.so` 即校验失败 | 构造兄弟文件场景 ⇒ exit 2 且列出非法文件 | ✅（代码路径）/ ⬜（负例实测） |
| FR-000-034 | MUST | **外部引擎库禁入**（node-runtime 统一供给，同名库重复会造成包内冲突） | 投放后检测到禁入文件即报错终止 | ✅（代码路径）/ ⬜（负例实测） |
| FR-000-035 | MUST | 投放幂等：门禁通过后落盘，重复投放结果一致 | 重复执行投放，目标内容与元数据一致 | ✅（实现）/ ⬜（全链未走通） |
| FR-000-036 | SHOULD | 投放成功后写入制品元数据（版本/ABI/文件名/大小/哈希/时间戳）供宿主查询 | 元数据文件生成且字段与实测一致 | ✅（实现）/ ⬜（未产生过） |

### 4.4 配置期持续集成（FR-000-040 ~ 042 族）

| 编号 | 级别 | 需求 | 可证伪的验收判据 | 现状 |
|---|---|---|---|---|
| FR-000-040 | MUST | CI 在无二进制的干净环境完成**配置期门禁**：任务求值必须成功 | CI 日志显示任务列举成功 | ✅ |
| FR-000-041 | MUST | CI 校验**退出码纪律**：未投放场景的校验命令退出码必须等于 2，其它非零视为工具缺陷 | CI 断言退出码 == 2 | ✅ |
| FR-000-042 | MUST | CI 对脚本做**语法门**：脚本必须可通过各自解释器的语法检查 | 语法检查零告警通过 | ✅ |

### 4.5 制品与随包数据（⬜ 规划引用，M1；编号待 M1 立项时进入 000-scaffold 之外的模块 spec）

| 需求（规划 §） | 级别 | 判据 | 现状 |
|---|---|---|---|
